# ScriptLab — Level 3 Implementation Plan

**Version:** 0.3 · **Date:** 2026-11-08 · **Status:** Proposed execution plan  
**Companion documents:** Architecture Blueprint v0.1; Technical Design Specification (TDS) v0.2  
**Primary execution environment:** Windows 11, Python 3.11+, Ollama, RTX 4060 laptop 8 GB VRAM, 16 GB RAM  
**Primary operator:** Human developer assisted by Claude Code; all source documents remain local by default.

## 1. Purpose and completion definition

This is an actionable delivery plan for a **local-first, model-independent RAG** that ingests hundreds of TV scripts and fan-fiction documents, extracts evidence-backed knowledge about characters and story chronology, and supplies compact source-cited context to Ollama or an explicitly approved premium model. It extends the Kitten board RAG pattern with scene/dialogue-aware parsing, character profiles, source isolation, and continuity checks.

**MVP complete means:** a clean Windows installation can import 20 representative documents; identify three characters; search dialogue, scenes, and continuity evidence with valid citations; generate and review five short scenes; and demonstrate that an unauthorized hosted-model call never occurs. A later expansion pass processes the full corpus without schema redesign.

**Out of scope for initial delivery:** fine-tuning, bulk copyrighted-text publication, scanned-PDF OCR, public internet hosting, fully autonomous season writing, automatic promotion of fan fiction into canon, and model-provider-specific assumptions about subscription entitlements.

## 2. Immutable engineering decisions

1. **SQLite is the system of record.** Source identities, normalized text spans, metadata, claims, jobs, manifests, and outputs live there. FTS5 is a SQLite search projection; ChromaDB is a rebuildable vector projection.
2. **Source class is mandatory:** `official`, `fanfiction`, `reference`, or `generated`. `canon` mode permits official material plus explicitly approved references, never fan or generated by default.
3. **All facts are evidenced.** A claim about a character or story event carries one or more source-span IDs and a review state; generated content is never treated as canon evidence.
4. **No business logic inside adapters.** CLI, Streamlit, FastAPI, MCP, Ollama and hosted providers use common typed Python services.
5. **No premium transmission without consent.** Hosted integration defaults disabled; present exact selected passages and destination before sending.
6. **Recoverability takes priority over throughput.** Jobs checkpoint at document/stage boundaries; retries are idempotent; one concurrent Ollama generation job initially.
7. **Version everything that may change conclusions:** parser, normalization, embedding model, extraction schema, prompt, source hash, generation parameters.

## 4. Setup and reproducibility (Phase 0)

### P0.1 — Bootstrap repository

**Files:** `pyproject.toml`, `README.md`, `.gitignore`, `.env.example`, `config/*.yaml`, `src/scriptlab/__init__.py`, `AGENTS.md`.

**Tasks:** create `C:\ScriptLab`; initialize Git; use a Python 3.11 virtual environment; install `ollama`, `pydantic`, `pyyaml`, `chromadb`, `fastapi`, `uvicorn`, `streamlit`, `pytest`, `httpx`, `python-docx`, `beautifulsoup4`, `lxml`, `pymupdf`, `ebooklib`. Record tested versions in a lockfile after successful installation. Create path configuration that resolves relative to a configurable project root, not the current directory.

```powershell
mkdir C:\ScriptLab
cd C:\ScriptLab
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
ollama list
ollama ps
```

**Tests:** `python -m pytest -q`; `python -m scriptlab.interfaces.cli doctor` reports Python, SQLite FTS5 availability, Ollama reachability, installed models, disk paths and writable directories without failing if Ollama is temporarily offline.

**Exit gate:** clean clone installs from project documentation; configuration validates; no secrets or corpus files tracked by Git.

### P0.2 — Design freeze and sample set

**Files:** `docs/decisions.md`, `tests/fixtures/manifest.json`, `tests/golden/README.md`.

Choose one initial TV series and a consistent `work_id`; choose 10 scripts and 10 fan works across formats and styles; manually label at least 100 script dialogue turns and 100 prose dialogue turns, plus 20 relevance queries. Keep the material private and store test metadata separately if fixtures cannot legally be committed. Record permission boundaries for hosted excerpts.

**Exit gate:** sample documents identified, evaluation set separated from profile-building material, unresolved decisions documented rather than guessed.

## 5. Canonical storage and provenance (Phase 1)

### P1.1 — Database migrations

**Files:** `store/db.py`, `store/migrations/0001_initial.sql`, `domain/schemas.py`, `tests/unit/test_schema.py`.

Translate TDS v0.2 §4 into migrations for `works`, `documents`, `source_spans`, `scenes`, `dialogue_turns`, `characters`, `aliases`, `claims`, `claim_evidence`, `relationships`, `events`, `chunks`, `jobs`, `model_runs`, and `generated_scenes`. Create appropriate unique indexes and foreign keys; enable `PRAGMA foreign_keys=ON`; establish WAL and a busy timeout. Add `schema_migrations` and reversible database backup before each schema upgrade.

**Provenance invariant:** every stored span references a document plus normalized character offsets and an SHA-256 of the span text. A source citation must resolve to the actual normalized text, even after a vector index rebuild. Normalized offsets are not original PDF byte offsets.

**Tests:** migration on empty database; rerun without changes; reject orphan references; verify cascading behavior; validate backup and restore; test integrity and foreign key checks.

**Exit gate:** database schema remains valid after interrupted and repeated migrations; 100% of inserted test spans round-trip to their source text.

### P1.2 — CLI and job ledger

**Files:** `interfaces/cli.py`, `ingest/jobs.py`, `tests/unit/test_jobs.py`.

Create commands: `doctor`, `db init`, `db check`, `import --path ... --source-type ... --work-id ...`, `jobs list`, `jobs resume --id ...`, `reindex`, `search`, `profile`, `generate-scene`. Implement statuses `queued`, `running`, `completed`, `failed`, `skipped`; checkpoint document/stage; record error summary and tool/prompt versions.

**Exit gate:** killing an import job at a checkpoint and rerunning it creates no duplicate records.

## 6. Readers, parsing, and normalization (Phase 2)

### P2.1 — File readers

**Files:** `ingest/readers.py`, `ingest/normalize.py`, `tests/unit/test_readers.py`.

Support UTF-8/legacy-encoded TXT, MD, HTML, DOCX, EPUB, and text-based PDF with explicit error reports. Preserve the original path and checksum; normalize Unicode and newlines while maintaining a stable offset map for normalized text. Reject empty/extraction-corrupted documents with actionable status rather than indexing them. Flag image-only PDFs as unsupported in the MVP.

**Outputs:** `ReadResult(document_id, sha256, format, normalized_text, metadata, warnings, parser_version)`.

**Tests:** mixed newline formats, encoding failures, HTML entities, duplicate files, PDF without text, documents with the same title but different hashes.

### P2.2 — Television script parser

**Files:** `ingest/parse_scripts.py`, `tests/golden/test_script_parser.py`.

Use deterministic rules first for scene headings, acts, stage directions, speaker cues, parentheticals, and dialogue turns. Maintain original speaker labels. Include style-specific parser plugins if sample scripts require them; never ask the LLM to resolve every line by default.

**Outputs:** validated scene records, ordered dialogue records, source spans, confidence/ambiguity flags. **Tests:** script headings with punctuation, CONT'D suffixes, offscreen voice markers, multiline dialogue, inconsistent indentation, unknown speakers and headings inside stage directions.

**Exit gate:** at least 95% of unambiguous sample script dialogue correctly attributed; every incorrect or uncertain line can be traced to its source span.

### P2.3 — Fan-fiction prose parser and aliases

**Files:** `ingest/parse_prose.py`, `ingest/normalize.py`, `tests/golden/test_prose_parser.py`.

Segment prose by chapters and scene breaks; detect quoted dialogue and nearby speaker attributions, but mark ambiguity explicitly. Add an alias-resolution queue for human review rather than silently merging two names. Preserve POV and narrative paragraphs as searchable passages.

**Exit gate:** report precision and coverage separately over 100 labeled dialogue turns; ambiguous attribution is visible and correctable; no unsupervised character-identity merges.

### P2.4 — Import acceptance

Import the 20-document fixture set twice, then compare document/scene/dialogue/span counts and keys. Verify that source type and work ID are required, not inferred from directories alone. Save an import report containing errors and skipped files.

**Exit gate:** zero duplicates after second import; original files unchanged; replay is safe after forced interruption.

## 7. Search indexes and hybrid RAG (Phase 3)

### P3.1 — Chunking and lexical indexing

**Files:** `index/chunk.py`, `retrieval/fts.py`, `tests/unit/test_chunking.py`, `tests/integration/test_fts.py`.

Create separate logical chunk kinds (`dialogue_exchange`, `scene`, `narrative_passage`, `claim_evidence`) with character/work/source/chronology metadata and stable span IDs. Target coherent units rather than uniform fixed-size blocks; cap large scenes and retain overlap metadata. Populate FTS5 from SQLite; make index rebuild deterministic.

**Tests:** exact phrases, special punctuation, Unicode, deletion/reindex, chronological filtering, no generated-source leakage.

### P3.2 — Ollama embeddings and Chroma

**Files:** `index/embed.py`, `index/chroma_store.py`, `tests/integration/test_vectors.py`.

Use `qwen3-embedding:0.6b` if present; confirm embedding dimensions at runtime. Batch requests conservatively, cache by content hash + embedding model identity, and store model/dimension metadata with each vector collection. Upsert deterministic chunk IDs; a changed embedding model produces a new versioned collection, never mixed dimensions.

**Tests:** repeat indexing without duplication; forced failure and resume; stale/deleted IDs reconciliation; vector search returns only resolvable SQLite chunks.

### P3.3 — Hybrid retrieval

**Files:** `retrieval/hybrid.py`, `retrieval/citations.py`, `domain/schemas.py`, `tests/golden/test_retrieval.py`.

Implement TDS §8: validate the work/source/timeline filters; retrieve up to 40 FTS5 and 40 semantic candidates; apply reciprocal rank fusion with default `k=60`; deduplicate overlapping spans; optional rerank; validate citations before response. Allow `canon`, `fan_influenced`, `alternate_universe` and explicit source-mode contracts. For strict timeline queries, unknown-dated material cannot silently be treated as earlier.

**Typed input:** `SearchRequest(query, work_id, source_mode, character_ids, timeline, k, token_budget)`. **Typed output:** `SearchResponse(query_id, results[], tokens_used, truncated, warnings[])`, each result with `chunk_id`, `span_id`, readable source metadata, score and chronology label.

**Adversarial tests:** a deliberately similar fan passage must not leak into canon-only retrieval; generated scenes cannot be evidence; fabricated IDs fail validation; source-embedded instructions are treated as data.

### P3.4 — Context package construction

**Files:** `retrieval/context.py`, `tests/unit/test_context_budget.py`.

Assemble compact source-mode rules, character traits, relationship/continuity evidence, relevant scenes, the writing prompt and recent-scene summary. Include a citation manifest and estimated tokens. Use a model-aware tokenizer when available; conservative fallback otherwise. Never consume the reserved output token budget.

**Exit gate for Phase 3:** 20 human-labeled retrieval queries yield a relevant top-five hit on at least 80%; all sampled citations resolve exactly; zero source isolation leaks; input context respects tested budget.

## 8. Character intelligence and continuity (Phase 4)

### P4.1 — Structured extraction

**Files:** `analysis/extract.py`, `analysis/prompts/*.md`, `domain/schemas.py`, `tests/unit/test_extract_validation.py`.

Use Ollama with schema-constrained output to propose traits, relationship claims, significant events and scene summaries. Every model-supplied evidence ID must already exist in SQLite and point to the analyzed source material. If malformed or unsupported, mark as rejected and retry a bounded number of times. Record prompt/model/version and throughput.

**Exit gate:** no fabricated source IDs accepted; extraction resumes after interruption; errors are reviewable.

### P4.2 — Claim consolidation and chronology

**Files:** `analysis/consolidate.py`, `analysis/profiles.py`, `tests/golden/test_claims.py`.

Merge semantically equivalent observations without deleting evidence, preserve contradictory interpretations, distinguish stable voice traits from transient emotional responses, and assign review status (`proposed`, `accepted`, `rejected`, `disputed`). Maintain story chronology independently from release order. Do not let fan interpretations overwrite official facts.

**Exit gate:** human reviewers accept at least 80% of a 50-claim sample as evidence-supported; contradictory claims remain inspectable; three initial character profiles have evidence links.

### P4.3 — Continuity checking

**Files:** `analysis/continuity.py` (or `writing/critique.py` domain service), `tests/golden/test_continuity.py`.

Compare proposed scene/outline events against indexed facts and requested timeline; return `supported`, `contradicted`, or `unknown` with evidence references. Unknown is never automatically treated as contradiction, and explicit alternate-universe mode can relax canon restrictions.

**Exit gate:** known spoiler/post-event traps are detected, with no invented citations.

## 9. Writing pipeline and quality review (Phase 5)

### P5.1 — Provider-neutral model contract

**Files:** `providers/base.py`, `providers/ollama.py`, `tests/unit/test_provider_contract.py`.

Define `generate(prompt, context, options) -> ModelResult`, including provider/model, token counts if reported, elapsed time, outputs and errors. Support local `qwen3:8b` drafting and optional `llama3.1:8b` critique with sequential model usage. Use bounded retries, timeouts and cancellation markers.

### P5.2 — Plan, draft, critique, revise

**Files:** `writing/plan.py`, `writing/draft.py`, `writing/critique.py`, `tests/integration/test_writing_mock.py`.

Generate a structured beat sheet (objective, conflict, turn, outcome), retrieve evidence, draft one scene, critique voice/relationships/continuity/repetition/source copying, optionally revise once, and persist every draft and context manifest under `generated/`. Keep output distinct from indexed canon. Run an overlap warning for unusually close matches to source passages.

**Tests:** mock-provider happy path; timeout midway; critique referencing nonexistent evidence rejected; saved manifests are reproducible; revision does not erase the original draft.

**Exit gate:** five scenes produced and reviewable, all with model metadata and citation manifests, with no known major continuity contradiction after human inspection.

## 10. API, premium models and MCP (Phase 6)

### P6.1 — Shared service and HTTP adapter

**Files:** `domain/service.py`, `interfaces/api.py`, `tests/integration/test_api.py`.

Expose `GET /health`, `POST /v1/search`, `GET /v1/characters/{id}`, `POST /v1/context`, `POST /v1/continuity/check`, `POST /v1/generate/scene`, `GET /v1/jobs/{id}`. Bind FastAPI to `127.0.0.1` by default. Enforce validation, output caps and structured errors (`INVALID_FILTER`, `NOT_FOUND`, `INDEX_STALE`, `BUDGET_EXCEEDED`, `AUTH_REQUIRED`). Never expose raw SQL or arbitrary-file endpoints.

### P6.2 — Premium provider boundary

**Files:** `providers/hosted.py`, `providers/approval.py`, `tests/integration/test_hosted_boundary.py`.

Keep `hosted_enabled: false` by default. Before a real hosted call, show the destination and exact excerpt package, estimated token consumption and consent decision. Redact credentials from logs; use environment variables or OS credential storage. Implement a mock premium provider and prove that all denied/disabled paths produce zero network calls. Only integrate a named vendor after verifying its current SDK and billing model; subscriptions are not assumed to include API usage.

### P6.3 — MCP adapter

**Files:** `interfaces/mcp_server.py`, `tests/integration/test_mcp_tools.py`.

Expose thin stdio MCP tools: `search_dialogue`, `search_scenes`, `get_character_profile`, `get_relationship`, `get_canon_facts`, `check_continuity`, `build_script_context`. Define JSON input/output contracts and size limits; reuse service logic. Test with a local MCP-compatible client before considering authenticated remote transport. Never assume a hosted website can reach localhost.

**Exit gate for Phase 6:** local API and MCP return equivalent citation-preserving evidence; premium call mock respects consent; no public listener is configured.

## 11. UI and corpus scale-up (Phase 7)

### P7.1 — Streamlit operator UI

**Files:** `app.py`, `tests/integration/test_ui_services.py`.

Implement five tabs: Library (imports/jobs/warnings), Characters (traits/evidence/corrections), Explore (hybrid search and filters), Generate (premise/continuity/model/approval), Evaluate (rubric, source links and comparisons). Manual edits change reviewed metadata or curated profiles, never source documents. All UI behavior routes through the shared service.

### P7.2 — Whole-corpus import and tuning

Import the remaining hundreds of documents in resumable batches. Profile total disk usage, peak memory, per-document analysis duration, embedding throughput, FTS/Chroma query latency and generation token use on the RTX 4060. Change batch sizes only on measured evidence. Document index rebuild and upgrade procedures.

### P7.3 — Ablation benchmark

With identical held-out scene prompts and model settings, compare four variants: (A) no retrieval, (B) hybrid RAG, (C) RAG plus character profiles, (D) RAG plus profiles and timeline/relationship data. Obtain blinded human reviews; record retrieval accuracy, voice fidelity, continuity violations, token usage and runtime. Adopt a component only when evidence supports it.

**Exit gate:** complete corpus imports with resumption; search results remain traceable; a user can switch from local Ollama to an approved hosted provider without changing database or retrieval code.

## 13. Defect handling, observability and operational runbook

**Failure classes:** `UNSUPPORTED_FORMAT`, `PARSE_AMBIGUOUS`, `OLLAMA_UNAVAILABLE`, `MODEL_OUTPUT_INVALID`, `INDEX_STALE`, `SPAN_HASH_MISMATCH`, `HOSTED_NOT_APPROVED`, `CONTEXT_TOO_LARGE`. Jobs must expose the actionable category, associated document/chunk ID, stage, retry count and safe summary; do not dump copyrighted excerpts into routine logs.

**Recover:** stop writer; back up SQLite using the SQLite backup API; run `PRAGMA integrity_check` and `foreign_key_check`; reconcile FTS and Chroma IDs; rebuild Chroma from SQLite if necessary; resume pending jobs. Backups include configuration, migration versions, prompt versions and generation manifests. Never use untested file-copy backup while SQLite has active writes.

**Security:** localhost binding; no public MCP endpoint for MVP; retrieved documents treated as untrusted input; source content never becomes a system instruction; no command execution from retrieved snippets; exact approved excerpt preview on hosted calls.

## 14. Claude Code execution protocol

Give Claude Code one numbered work package at a time, along with the TDS v0.2 and this plan. Require it to inspect existing files before edits; preserve public service contracts; implement code + tests together; run the designated test gate; provide changed-file list, commands run, test results, known gaps and next recommended task. Commit only after human review of each gate.

**Starter task prompt:**

> Implement P1.1 (SQLite migrations and provenance schema) in the existing ScriptLab repository. Follow the Technical Design Specification v0.2 §4 and the Level 3 Implementation Plan v0.3. Do not implement ingestion, vector search, UI, hosted APIs or MCP yet. Add migration and schema tests, run them, and report changed files and any design choices that need approval. Preserve the rule that SQLite is authoritative and Chroma is rebuildable.

**Stop and request a decision** if a task requires changing a frozen data contract, granting hosted-model transmission, overwriting source files, publishing a service externally, or introducing a substantial new dependency.

## 16. Open decisions before major development

- Select the first series and canonical `work_id`, plus how alternate continuities are represented.
- Sample real file formats and determine whether any scanned PDFs need a later OCR extension.
- Agree on which source excerpts, if any, may be transmitted to hosted AI providers.
- Verify exact installed Ollama model tags and measure memory/latency on the laptop.
- Choose initial consumer: CLI, Streamlit, Claude Code local MCP, or an API-driven hosted client.
- Choose whether to introduce relationship labels specific to the selected fandom in a later schema revision.

**Final design rule:** ScriptLab is a durable, evidence-backed fictional-universe RAG service. Models, user interfaces and transport adapters should be replaceable without re-ingesting the corpus or losing provenance.
